# Fase-0 benchmark scripts

Runnable version of protocol sections 7 and 8 of
[`plan_agente_liviano_refutado.md`](../plan_agente_liviano_refutado.md).

Purpose: measure **private RAM** and **CPU** of `opencode` and Gentle Shell
under the same conditions, so the rewrite-vs-keep decision is made on data
instead of single samples. Everything runs on Windows PowerShell (5.1 or 7;
development used 7.6.6).

## Files

| File | Role |
| --- | --- |
| `ProcessTree.ps1` | Tree sampler module. Sums the whole process tree from one root PID, records **both** `WorkingSet64` and `PrivateMemorySize64`, and keeps a per-PID attribution CSV with `CommandLine` (so MCP children are identified, not assumed). |
| `Start-Benchmark.ps1` | One scenario run: preconditions, root detection, sampling loop, CSV output. |
| `Compare-Benchmark.ps1` | Aggregates all run CSVs into the section 7.4 decision table (markdown). |

Outputs land in `bench/results/` (git-ignored on purpose):

```
samples_<tool>_<scenario>_run<N>.csv     tree totals, one row per sample
processes_<tool>_<scenario>_run<N>.csv    one row per distinct PID seen
benchmark_report_<timestamp>.md           generated by Compare-Benchmark
```

## Preconditions (protocol 7.1)

1. Close **every** agent tool first except the one under test. The script
   refuses to run if it detects the other tool alive.
2. Use the **same repository** for both tools. Default: `D:\socialemperors`
   (`-Repo` to override).
3. Same duration per scenario: 30 minutes, **3 repetitions** per scenario.
4. Record the model and provider used for each run (paper notebook is fine;
   the CSV does not capture them).
5. Keep unrelated heavy programs closed; note anything that could add noise.

## Scenarios

| Scenario | Meaning | How to produce it |
| --- | --- | --- |
| `A` | Idle right after start | Start the tool, open the repo, run the script, do not touch it. |
| `B` | Active task | Start the script, then drive the workload script below yourself. |
| `C` | With ONE subagent active | Start the script, launch exactly one subagent in the tool and keep it working. Pass `-Label subagent-1` **and** `-NewProcessPattern 'gentle-shell\.mjs|pi-coding-agent'`: gentle-shell subagents are **sibling agent sessions** (their own launcher + cli.js), NOT children of the measured session, so a single-root tree cannot see them (verified live 2026-10-09). The pattern includes matching processes created during the run only, so an unrelated second window does not pollute the sample. |
| `D` | After ~30 min of session | Work normally for ~30 min, then run the script. It samples the window, not the session lifetime; growth here is window growth. |

### Workload script (used for B, C, D)

Same five tasks in the same repo for both tools:

1. read two or three files (`read` with offset/limit),
2. grep for a symbol across the repo,
3. edit one file (small, revertible change; undo via git),
4. run the project test suite,
5. ask for a summary of the change.

### Commands

```powershell
# Scenario A, run 1, opencode
pwsh -File bench\Start-Benchmark.ps1 -Tool opencode -Scenario A -Run 1

# Scenario B, run 2, Gentle Shell, 30 minutes, 60 s interval
pwsh -File bench\Start-Benchmark.ps1 -Tool gentle-shell -Scenario B -Run 2 -DurationMinutes 30 -IntervalSeconds 60

# Scenario C with a label and sibling capture
pwsh -File bench\Start-Benchmark.ps1 -Tool gentle-shell -Scenario C -Run 1 -Label subagent-1 -NewProcessPattern 'gentle-shell\.mjs|pi-coding-agent'

# Smoke test the machinery (never writes real run files)
pwsh -File bench\Start-Benchmark.ps1 -Tool auto -Scenario A -Run 9 -ProcessId <PID> -DryRun

# Report over everything collected
pwsh -File bench\Compare-Benchmark.ps1
```

## How the root PID is found

- `opencode`: the process named `opencode`; its MCP children fall inside the
  sampled tree.
- `gentle-shell`: the `node` process whose command line contains
  `pi-coding-agent/.../cli.js`, then the script walks up `ParentProcessId` to the
  first ancestor that is not a shell (`cmd`, `powershell`, `pwsh`,
  `WindowsTerminal`, `conhost`, `explorer`).

**Subagents are siblings, not children (measured).** A gentle-shell subagent
spawns its own `gentle-shell.mjs` + `pi-coding-agent` process pair, parented
to the launcher shell, NOT to the measured session. For scenario C always
pass `-NewProcessPattern 'gentle-shell\.mjs|pi-coding-agent'`; matching
processes are included only if created after the run started, so a second
window opened *before* the run is excluded. One opened *mid-run* is
indistinguishable from your subagent: do not open other agent windows while
sampling scenario C.

Override any time with `-ProcessId <PID>`.

## Cheap levers before the benchmark (plan section 8)

Test these while collecting baseline data; they cost nothing:

1. opencode config: `snapshot: false`, `compaction.auto/prune` (already applied).
2. `/new` per task; close unused spaces; check `opencode.db` size.
3. **Heap cap for Node (Pi) — hypothesis, unproven**:
   `$env:NODE_OPTIONS = '--max-old-space-size=256'` then start Gentle Shell
   and watch `Private_MB`. Risk: out-of-memory errors in very large sessions.
4. Read files with `offset/limit` instead of full loads.
5. Update both tools; check changelogs for memory fixes.

## Limits of this harness

- It measures **one OS process tree per tool**, not GPU/VM overhead.
- CPU is process CPU time deltas over wall clock, expressed as percent of one
  core (plan 7.4 metric), not system-wide usage.
- Windows working sets include shareable pages; that is why **private** MB is
  the decision metric (plan 5, correction #3).
- The scripts sample while a human works; they do not replay workload
  keystrokes. Consistency of the workload script above is on you.
- **Observer cost**: every sample enumerates all `Win32_Process` objects.
  At 20 s intervals that adds measurable CPU inside the measured tree
  (seen: ~14% of one core during an active task). Keep 60 s for the
  protocol runs and do not run two samplers at once.
- **CPU is a tree sum deltas**: processes exiting mid-window remove their
  accumulated CPU (undercount); processes joining bring theirs in. Prefer
  windows without restarts of MCPs or helper processes.
